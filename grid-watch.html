Feeding the briefing in two routes; the relay does not care which

The Briefing tab compares today's run against the previous one. That only works if each run reaches the relay. If whatever writes your brief can make an HTTP request, post it. If it can only send email — which is the usual case when the brief is generated somewhere you do not control — the relay will read it out of a mailbox instead.

Route 1 — POST the structured block after each run Whatever runs your daily brief should end by posting its STRUCTURED block to /digest.json with the token above in an X-Relay-Token or Authorization: Bearer header. The relay keeps the last few hundred, which is over a year of daily runs.

Until something arrives the diff has nothing to compare and every item reads NEW forever — which the panel says, rather than implying a quiet day.
Route 2 — let the relay read a mailbox Set BRIEFMAIL_ENABLED=true in relay.env and point it at either a local maildir (BRIEFMAIL_MAILDIR, no credentials involved) or an IMAP account (BRIEFMAIL_IMAP_*). Send or forward the brief there and it is ingested on the next sweep.

Anyone can send mail to any address, so the sender is not the control: the brief's structured block must carry BRIEFMAIL_SECRET as its token field or the relay refuses it. A From allowlist is available and is a convenience — it stops accidents, not forgeries, and the relay says so rather than implying otherwise.
Before the prompt emits a block A brief that arrives as prose is still ingested, but only what is exact is taken from it: CVE, ICSA, 202(c) and FERC identifiers, which either appear in the text or do not. Those rows are marked scanned from text and they diff correctly against a later structured run, because the identifier strings are the same strings.

Nothing numeric is read out of prose. A load figure scraped from a sentence would land in the same field as one the briefing asserted, and the two are not the same claim.
What the block needs to carry A stable identifier per item, or day-over-day matching is guesswork. CVE IDs, ICSA numbers, 202(c) order numbers and FERC dockets are exact. RTO alerts have no natural identifier and want a composite key of ISO plus type plus effective date. Cyber incidents have none at all — those need a synthesized slug, and the match should be marked fuzzy rather than pretended precise.

Latency, honestly. This is the freshest broad public feed for the US grid, but it is not real-time SCADA. Demand and day-ahead forecast typically land 1–2 hours behind; net generation and interchange 12–14 hours behind; BA-to-BA interchange over a day behind. A dashboard that pretended otherwise would be worse than none. For sub-minute visibility you need ISO/RTO real-time feeds or E-ISAC/OT telemetry, which are not public.

Interpretation. Deviation flags are statistical, not causal. Weather, forced outages, market behaviour, holidays and EIA's own data revisions all produce excursions. Treat a flag as a prompt to correlate against ISO notices, weather, and your own sources — never as an indicator of a security event on its own.

Outage tabs. Customer outage counts come from the Outage Data Initiative Nationwide (ODIN), run by Oak Ridge National Laboratory with the U.S. Department of Energy's Office of Electricity and served from ornl.opendatasoft.com without a key: county-level, near-real-time, including reported cause, crew status, estimated restoration time and customers already restored where the filing utility supplies them. Participation is voluntary, so coverage is partial — a county with no record is one nobody reported, not one with the lights on, and every ODIN total should be read as a floor. The portal allows 5,000 calls a day, so this layer refreshes at most every five minutes regardless of the auto-refresh interval, and the remaining quota is shown on the tab. Active weather alerts come from the National Weather Service API (api.weather.gov/alerts/active), live and unauthenticated; the configured state's county roster is its own zone list. Generator outages are EIA-860M status codes — standby, out of service expected to return, out of service not expected to return — a monthly snapshot rather than a live trip signal. Load loss is inferred from the same demand-deviation engine as the other tabs, which matters most exactly where ODIN has no reporters. Nothing here describes crews, circuits, switching state or damage assessment beyond what a utility itself files; that is utility OT and GIS data. Treat every reading as informational.

Running it unattended. The Auto control sets the refresh interval and is remembered in this browser. Most cycles cost a single request: the page first asks EIA whether a newer hour has been published and only reloads in full when one has, so a one-minute interval is not sixty full reloads an hour. Scheduling works off wall-clock time rather than a timer chain, because browsers throttle timers in background tabs — a tab that has been hidden refreshes as soon as it is looked at again if it fell behind. A failed update keeps the last good screen up rather than blanking it, retries with exponential backoff, and says plainly at the top that what you are reading is not current; the same banner appears if EIA's own newest hour falls more than four hours behind. The browser tab title carries the flagged-BA count so a background tab still shows it, and Changes since this page was opened logs every flag that opened or cleared while you were away.

Key handling. The EIA API key is embedded in this file and is sent to api.eia.gov only. It is a free, rate-limited, read-only key over public data. Anyone you hand this file to gets the key — rotate at eia.gov/opendata if that matters, or use the ⚙ Key control to run with a different one.
